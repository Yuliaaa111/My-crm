# План: реализация My CRM

Упрощённая версия [harryho/react-crm](https://github.com/harryho/react-crm)
на нашей архитектуре (MVVM, файловый роутинг, моки) с JWT-авторизацией
и светлой/тёмной темой. Код пишется с нуля, тексты интерфейса — свои.

## Что берём из оригинала и что упрощаем

| В оригинале                                 | У нас                                                          |
| ------------------------------------------- | -------------------------------------------------------------- |
| Вход с любым непустым паролем               | Вход по учётным данным из моков, JWT с `exp`                   |
| Dashboard: 4 показателя, 6 графиков, лента  | 4 показателя, 3 графика, последние заказы                      |
| Users: таблица, поиск, форма                | `customers`: таблица, поиск, фильтр, создание/правка/удаление  |
| Products: карточки, фильтр, варианты товара | `products`: таблица, поиск, фильтр по категории, без вариантов |
| Orders: список, детали, оплата, доставка    | `orders`: список, детали, создание, смена статуса              |
| Cart, Checkout, Inventory, Blogs, Agents    | не делаем                                                      |
| MUI + Toolpad, ApexCharts, MSW, Storybook   | свои компоненты на Emotion, Recharts, моки в `model/`          |

Упрощения модели данных:

- товар без вариантов: одна цена, один артикул, один остаток;
- у клиента один адрес (город, страна), без списка адресов;
- заказ без оплаты и доставки: статус меняется вручную
  (`pending` → `paid` → `processing` → `shipped` → `delivered`, плюс
  `cancelled`), история смены статусов сохраняется;
- заказ хранит имя клиента и названия товаров на момент оформления;
- данные живут в памяти и сбрасываются при перезагрузке страницы (как в
  оригинале); сохраняются только сессия и тема.

## Отступления от эталона `setup-tooling` (согласованы 01.10.2026)

1. **`eslint-plugin-import` и `eslint-plugin-react` не ставлю.** В
   проекте ESLint 10.11.0, а оба плагина поддерживают только ESLint 9
   и ниже. Вместо первого — `eslint-plugin-import-x` (поддерживает
   ESLint 10, те же три правила). Второй не заменяю: его проверки
   покрывают TypeScript и `eslint-plugin-react-hooks`.
2. **Из запретов линтера убираю `unknown`** — мы его разрешили. Запрет
   `any` остаётся. Добавляю запрет `interface`, `enum`, `satisfies` и
   `export default` внутри `src/`. Полного запрета `as` из эталона нет
   (правило уточнено 02.10.2026): `as const` разрешён; обычный `as` без
   комментария на той же или предыдущей строке — ошибка (собственное
   правило `local/commented-type-assertion`); `as any`,
   `as unknown as X` и `<Type>value` — ошибка.
3. **`tsconfig` остаётся разделённым** (`tsconfig.app.json` +
   `tsconfig.node.json`), эталон не накатываю поверх. Добавляю `strict`,
   `paths` для `@/`, включаю в проверку `eslint.config.ts`.
   `useUnknownInCatchVariables: false` из эталона не беру — с ним ошибка
   в `catch` получает тип `any`.
4. **Из эталонов убираю всё про `API_BASE_URL` и генератор типов** —
   бэкенда нет.
5. **husky и lint-staged не ставлю** — в скилле их нет. Скажите, если
   нужны.

## Общие правила для каждого этапа

- Ветка `feature/<имя>` от свежей `develop`.
- Шаги этапа отмечаются в этом файле по мере выполнения.
- Перед сдачей этапа: `npm run typecheck`, `npm run lint`,
  `npm run build` без ошибок; самопроверка по `.claude/rules/`.
- После сдачи — жду вашего подтверждения. Коммит, слияние в `develop` и
  push — только после него.
- Если по ходу этапа понадобится изменить правила в `.claude/rules/` —
  сначала спрашиваю.
