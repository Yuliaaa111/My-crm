# Commit

Коммит — не деструктивная операция сама по себе (не push, не удаление,
не изменение чужого кода), поэтому этот скилл может срабатывать и по
`/commit`, и по обычной просьбе закоммитить, сформулированной любыми
словами. Правило "не коммитить самостоятельно" из
`.claude/rules/safety-rules.md` при этом не нарушается: скилл
запускается только в ответ на выраженную пользователем просьбу
закоммитить, а не по инициативе модели без повода.

## Шаги

1. Выполнить `git status --porcelain`. Если изменений нет — сообщить
   пользователю, что коммитить нечего, и остановиться, не выполняя
   дальнейшие шаги.
2. Показать пользователю краткую сводку того, что будет закоммичено
   (список изменённых/новых файлов из `git status`).
3. Определить текущую ветку: `git rev-parse --abbrev-ref HEAD`.
4. **Защита `main`/`master`.** Если текущая ветка — `main` или
   `master` — сообщить об этом пользователю до выполнения `git add`/
   `git commit` и уточнить, как поступить (например переключиться на
   новую ветку), вместо того чтобы продолжать как обычно. Действует
   правило `safety-rules.md` и, если настроен, хук
   `protect-main-branch.sh` — коммит/push напрямую в `main`/`master`
   не выполняется даже при согласии пользователя на push дальше по
   шагам.
5. Выполнить `git add .`.
6. **Сформировать название ветки для заголовка коммита:** если первый
   символ имени ветки — строчная буква, сделать её заглавной (только
   первую букву, остальное имя ветки не менять); если ветка уже
   начинается с заглавной буквы или не с буквы — оставить как есть.
   Например ветка `feature-login` → `Feature-login`.
7. Сгенерировать текст коммита на английском языке — короткое,
   содержательное описание того, что изменилось, на основе
   `git diff --staged` (не общая фраза вроде "update files").
8. Итоговое сообщение коммита собрать строго в формате:
   `[<Ветка с заглавной первой буквой>] <Текст на английском>`,
   например `[Feature-login] Add email validation to login form`.
9. **Сообщение всегда однострочное. Строгий формат вызова:**
   `git commit -m "[Ветка] Текст"`.
   - Не добавлять вторую строку или тело коммита.
   - Не добавлять trailer-строки вроде `Co-Authored-By`,
     `Generated with`, ссылки на модель/инструмент и подобное.
   - Не оборачивать команду в `$(cat <<'EOF' ... EOF)` или любые
     другие multiline-конструкции — только прямой `-m` с одной
     строкой в кавычках.
   - Делать так всегда, даже если это отличается от того, как Claude
     Code мог бы оформить коммит по умолчанию без этого скилла.
   - Исключение — если пользователь сам явно попросил
     multiline-сообщение или соавторство в этом конкретном коммите.
10. Выполнить `git commit -m "<итоговое сообщение>"`.
11. **Проверить, что коммит реально создан:** выполнить
    `git log -1 --oneline` и сверить, что верхний коммит соответствует
    только что созданному (по сообщению и/или хэшу). Показать
    пользователю результат проверки — хэш и сообщение коммита.
12. **Спросить у пользователя разрешение на `git push`** — не делать
    push автоматически ни при каких условиях. Дождаться явного
    "да"/"нет".
13. Если пользователь подтвердил — выполнить `git push` (с
    `-u origin <branch>`, если у ветки ещё нет upstream). Если
    пользователь отказался — оставить изменения закоммиченными только
    локально и на этом остановиться.
